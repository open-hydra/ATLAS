# GPB Output Files

## Output Directory

GPB writes generated files to:

```text
fromATLAStoSolver/
```

They are staged in a temporary directory `.gpb-tmp-<random>/`, a new one for every run, while the deck is built and moved into `fromATLAStoSolver/` only when every phase succeeded (a refusal leaves nothing; pre-existing files are never removed).

## Naming Convention

For each GPB section, the output filename prefix is built from the section `name` key:

- if `name = air`, prefix is `air-`
- if `name` is omitted, prefix is empty

So files are emitted as:

```text
fromATLAStoSolver/<prefix><suffix>
```

where `<suffix>` depends on the phase/type (see below).

## File Format

GPB currently writes plain-text files (Tecplot-style `.dat` plus descriptor `.txt`).

## Ideal-Gas Outputs

Generated by `src/GPB/ideal_gas/io.py`.

### `<prefix>phase.txt`

- first line: `ideal-gas phase`
- then one line per species:

```text
<species_name> <molecular_weight>
```

### `<prefix>thermo.dat`

Tecplot point format with one zone per species.

Variables:

1. `Temperature`
2. `Cp`
3. `Enthalpy`
4. `Entropy`
5. `dCp`

Temperature grid is integer-spaced from `Tmin` to `Tmax` (inclusive), step 1 K: `Tmin` and `Tmax` are integers.

### `<prefix>transport.dat`

Tecplot point format with one zone per species.

Variables:

1. `Temperature`
2. `Viscosity`
3. `Conductivity`


### `<prefix>diffusion.dat`

Tecplot point format with binary diffusion coefficients for every unique species pair.

Variables:

1. `Temperature`
2. `Binary coefficient ij`

### `<prefix>composition.txt`

The elemental composition of the species: the number of elements and their names, then, after the line
`composition`, one row per species with its number of atoms of each element.

```text
2
H
O

composition
1 0
2 0
0 1
...
```

### Chemistry (when reactions are processed)

Finite-rate chemistry files for reactive simulations, if reactions are processed:

- `<prefix>chemistry-info.txt`
- `<prefix>chemistry-Arrhenius.dat`
- `<prefix>chemistry-Troe.dat`
- `<prefix>chemistry-Lindemann.dat`

In the Troe and Lindemann tables the column `k_c` is written as 0 on every row of an **irreversible** falloff reaction (`=>`): no backward rate exists (reversible reactions are unchanged). Use these tables with the FLINT released with this ATLAS version; how FLINT reads `k_c = 0`, and what older versions do with it, is described in [FLINT's documentation of the table formats](https://github.com/MarcoGrossi92/FLINT/blob/main/docs/user/input/native.md) (`docs/user/input/native.md` of the FLINT repository).
`chemistry-info.txt` ends with the block `Reaction orders` / `<n>` / `<ir> <species> <order>` (`ir` = index in the `Reaction type` list): the explicit `orders:` of the yaml, `n = 0` when it gives none; orders given on a falloff reaction are not written (the tables carry orders for the Arrhenius-type reactions only) and GPB prints a WARNING.

The `chemistry-info.txt` file contains a summary of the reactions and their parameters, while the `chemistry-*.dat` files are Tecplot point datasets with one zone per reaction and `Temperature` as the first variable and forward/backward rates.

## Condensed / Solid Outputs

Generated by `src/GPB/condensed/io.py`.

### `<prefix>phase.txt`

Line 1 is the phase type word exactly as the solver readers expect it, optionally followed by the `modeling` token:

```text
condensed-dispersed modeling=lagrangian
```

- the type word is `condensed-dispersed`, `liquid-dispersed` or `solid-dispersed` for a dispersed phase (it is the `type` you wrote), or `solid-bulk` for a solid phase (`type = solid` and `type = solid-bulk` both write `solid-bulk`)
- ` modeling=lagrangian` or ` modeling=eulerian` is appended only when `[GPB-Phase*] modeling` is set; it is ignored for a solid phase. Hydra checks it against the solver that takes the phase
- then one line per material: the material name, the number of groups, and zero or more configured `key=value` tokens; tokens are space-separated and never contain `=` elsewhere

```text
<material_name> <groups>[ key=value ...]
```

### `<prefix>properties.dat`

Tecplot point format with one zone per species/material and an integer-spaced temperature grid from `Tmin` to `Tmax` (inclusive).

If type contains `dispersed`, variables are:

1. `Temperature`
2. `Cp`
3. `Density`
4. `Enthalpy` or `Enthalpy_abs`
5. `Psat`
6. `Lv`
7. `Mv`
8. `Cpv`

columns 5–8 only when `psat-vapour` pairs at least one material.

The fourth name tags the enthalpy datum; columns 2–4 keep this order, which ATLAS's own readers rely on. `Enthalpy` is relative (`cp·T` for constant-`cp` materials, the `SP-database` integral from `Tmin`); `Enthalpy_abs` is absolute, i.e. it includes the enthalpy of formation (every `thermo` table, and constant-`cp` materials given `h0`, see [Condensed & Solid Phases](./condensed-solid.md)). `Psat` is the saturation pressure [Pa, written `%.6e`], `Lv` the latent heat [J/kg], `Mv` the molar mass of the vapour [kg/kmol] and `Cpv` its specific heat [J/(kg·K)], all four from the database's liquid/vapour pair (see [Condensed & Solid Phases](./condensed-solid.md)) and zeros for a material that is not paired; the solvers find them by name.

Otherwise variables are:

1. `Temperature`
2. `Cp`
3. `Density`
4. `Conductivity`
5. `Energy`

### `<prefix>models.txt`

Generated by `src/GPB/condensed/io.py`, written only when a material of the phase has burning-model, cap or breakup
constants (`combustion`, `cap`, `breakup`; none written for a phase where no material has them). Row grammar, the constants
each model reads, and the solver-facing rules are in [Condensed & Solid Phases](./condensed-solid.md#the-constants-of-the-models-namemodelstxt).

### `<prefix>products.txt`

Generated by `src/GPB/condensed/products.py` (run once, after every `[GPB-Phase*]` is built), for every dispersed
phase when the deck has exactly one ideal-gas or heavy-gas phase (with none or several, no file is written, and a
dispersed phase that names `particle-mechanism` stops GPB). It maps each material of the phase to the gas species
its evaporation, combustion or cap reaction gives and, when the reaction makes one condensed product, to that
product; hydra-MI2 is its only reader (`INPUT/<prefix>products.txt`).

Header:

```text
# ATLAS GPB: condensed material -> gas species. Generated: edit the INI and run ATLAS GPB again.
# particle-mechanism: <mechanism name> (<path to the yaml>)
# record: material <name> <none|evaporation|combustion|cap|release> <terms> <none|latent|formation> <h298 [J/kg]>
#         then <terms> lines: <gas species> <nu_mass [kg/kg material]> <nu_mole [mol/mol material]>
#         a cap record ends with: <product material> <kg of it per kg of material> <its h298 [J/kg]>
gas <gas phase prefix, or `-` when it has none> <number of gas species>
```

then one block per material of the phase:

```text
material <name> <process> <terms> <energy word> <h298 [J/kg]>[ <product> <nu_prod> <its h298>[ <smoke's phase prefix>]]
  <species> <nu_mass> <nu_mole>
  ... (<terms> lines)
```

- `<process>` is one of `none` (nothing consumes the material: `<terms>` is 0, no term line follows), `evaporation`
  (energy word `latent`; one term, the material's own vapour), `combustion` (the particle-mechanism reaction that
  burns the material), `cap` (the reaction that gives its oxide cap) or `release`: for a material that is another
  material's cap oxide (its `product=`), the reaction that hands that oxide to the gas as gas species; or, for an
  oxide cap that is itself a smoke and that no reaction consumes, a record of 0 terms whose tail still carries the
  product tail below (the cap born as smoke whole). Evaporation, combustion, cap and release are written as
  separate blocks of the materials they apply to; a material runs at most one of each.
- Every `<terms>` line is a gas species the reaction gives or takes, `nu_mass` [kg of species per kg of material]
  and `nu_mole` [mol of species per mol of material] (both signed: negative for a species the reaction consumes).
- A `cap` record ends with the oxide cap the material retains: `<product material>`, the kg of it per kg of
  material, and its `h298`.
- A `combustion` or `release` record whose reaction makes one condensed product ends with that product the same
  way (`<product> <nu_prod> <its h298>`); when the product is a **smoke** — a material of an *eulerian* dispersed
  phase with a population, born in that phase's ICE family (see
  [Condensed & Solid Phases](./condensed-solid.md#the-smoke-of-a-burning-material)) — one more token follows: the
  output prefix of the eulerian phase that receives it (`-` when that phase has no `name`). hydra-MI2 reads this
  last token to route the smoke's mass into the right ICE family.

Example (`test/GPB/CP-smoke-ice/reference/part-products.txt` of ATLAS's own test suite: AL(L) burns with steam
into AL2O3(L), a smoke of the same eulerian phase `part`, and H2):

```text
# ATLAS GPB: condensed material -> gas species. Generated: edit the INI and run ATLAS GPB again.
# particle-mechanism: al-h2o-smoke (./al-h2o-smoke.yaml)
# record: material <name> <none|evaporation|combustion|cap|release> <terms> <none|latent|formation> <h298 [J/kg]>
#         then <terms> lines: <gas species> <nu_mass [kg/kg material]> <nu_mole [mol/mol material]>
#         a cap record ends with: <product material> <kg of it per kg of material> <its h298 [J/kg]>
gas gas- 3
# 2 AL(L) + 3 H2O => AL2O3(L) + 3 H2
material AL(L) combustion 2 formation 3.2133040798e+05 AL2O3(L) 1.8894415005e+00 -1.6058800507e+07 part-
  H2O -1.0015181343e+00 -1.5000000000e+00
  H2 1.1207663385e-01 1.5000000000e+00
material AL2O3(L) none 0 none 0.0000000000e+00
```

AL(L)'s combustion record ends with its smoke, AL2O3(L), and the trailing `part-` (the output prefix of
`[GPB-Phase2]`, which hydra-MI2's `part` ICE family reads); AL2O3(L) itself has no reaction of its own (`none`).

## Pyrolysis-Gas Tables

Generated by `src/GPB/pyrolysis/io.py` when the deck has `[GPB-Pyrolysis<n>]` sections:
`<prefix>pyrolysis.dat`, with the prefix of the ideal-gas phase the section names, one table per section in the
order of `n`. The format is in [Pyrolysis-Gas Tables](./pyrolysis.md#the-table).

## Real-Fluid Outputs

Generated by `src/GPB/real_fluid/io.py`.

### `<prefix>phase.txt`

Two lines:

1. `real-fluid phase`
2. fluid name

### `<prefix>thermo.dat`

Tecplot block format with zone dimensions `I=NP`, `J=NH`.

Variables:

1. `Pressure`
2. `Enthalpy`
3. `Density`
4. `Temperature`
5. `dRho/dT`
6. `dRho/dh`
7. `Cp`
8. `Entropy`
9. `dRho/dp`
10. `SoundSpeed`

### `<prefix>transport.dat`

Tecplot nodal dataset for the same `NP x NH` table.

Variables:

1. `Pressure`
2. `Enthalpy`
3. `Viscosity`
4. `Conductivity`

## Examples

### Example 1: ideal-gas section with `name = air`

If your INI section contains:

```ini
[GPB-Phase1]
type = ideal-gas
name = air
```

GPB writes files such as:

- `fromATLAStoSolver/air-phase.txt`
- `fromATLAStoSolver/air-thermo.dat`
- `fromATLAStoSolver/air-transport.dat`

Example `air-phase.txt`:

```text
ideal-gas phase
N2 28.013400
O2 31.998800
```

Example first lines of `air-thermo.dat`:

```text
TITLE = "Mass Thermodynamic Properties"
VARIABLES = "Temperature", "Cp", "Enthalpy", "Entropy", "dCp"
ZONE T="N2"
I=5000, F=POINT
```

### Example 2: condensed-dispersed section with `name = alumina`

If your INI section contains:

```ini
[GPB-Phase2]
type = condensed-dispersed
name = alumina
```

GPB writes files such as:

- `fromATLAStoSolver/alumina-phase.txt`
- `fromATLAStoSolver/alumina-properties.dat`

Example `alumina-phase.txt`, for `material = AL2O3(L)`:

```text
condensed-dispersed
AL2O3(L) 1
```

Example first lines of `alumina-properties.dat`, for `thermo = NASA9` (the default range, 1 K to 5000 K):

```text
TITLE = "Mass Thermodynamic Properties"
VARIABLES = "Temperature", "Cp", "Density", "Enthalpy_abs"
ZONE T="AL2O3(L)"
I=5000, F=POINT
```

### Example 3: real-fluid section with `name = n2rf`

If your INI section contains:

```ini
[GPB-Phase3]
type = real-fluid
name = n2rf
fluid = Nitrogen
NP = 200
NH = 200
```

GPB writes files such as:

- `fromATLAStoSolver/n2rf-phase.txt`
- `fromATLAStoSolver/n2rf-thermo.dat`
- `fromATLAStoSolver/n2rf-transport.dat`

Example `n2rf-phase.txt`:

```text
real-fluid phase
Nitrogen
```

Example first lines of `n2rf-thermo.dat`:

```text
TITLE = "Mass Thermodynamic Properties"
VARIABLES = "Pressure", "Enthalpy", "Density", "Temperature", "dRho/dT", "dRho/dh", "Cp", "Entropy", "dRho/dp", "SoundSpeed"
ZONE T=real-gas, I=200, J=200, K=1, DATAPACKING=BLOCK, VARLOCATION=([1-10]=NODAL)
```

### Example 4: omitted `name`

If `name` is omitted, filenames do not get a prefix. For an ideal-gas section this means files are:

- `fromATLAStoSolver/phase.txt`
- `fromATLAStoSolver/thermo.dat`
- `fromATLAStoSolver/transport.dat`
